# 价目表图片 OCR 与京东全国最低价设计

## 状态与决策

本设计于 2026-09-03 获得用户整体批准。首版只支持京东，采用本机 PaddleOCR 识别竖版手机价目表，并按“型号 + 容量 + 颜色”精确比价。每个规格核验中国大陆 31 个省级地区的固定代表街道，只保留一条低于价目表价格的最低结果。

本功能建立在《京东 31 地区四级地址选择设计》之上。四级地址能力是批量比价的前置条件，必须先完成并通过离线测试。

## 目标

用户完成一次操作链即可得到可追溯的最低价：

1. 上传一张 JPG、PNG 或 WebP 价目表；
2. 本机 OCR 识别日期、型号、容量、颜色和今日价；
3. 在可编辑表格中校对低置信度或错误字段；
4. 确认需要查询的规格；
5. 系统按顺序查询京东，并对每个规格核验 31 个固定代表街道；
6. 以明确的普通优惠券和明确适用的国补计算可信到手价；
7. 每个精确规格只展示一条低于今日价的最低结果。

## 非目标

- 不接入淘宝、天猫或拼多多；
- 不支持任意表格、聊天截图、手写单据或多页 PDF；
- 不忽略颜色，也不把相近颜色自动合并；
- 不把 OCR 记录自动写入正式商品目录；
- 不使用云端 OCR，不上传原图到第三方；
- 不保存原图、平台 Cookie、账号密码、验证码或完整页面 HTML；
- 不自动下单、加购物车或进入结算；
- 不扣减 PLUS、会员、支付、以旧换新、分期、新人或预约条件优惠；
- 不绕过登录、验证码、风控或访问频率限制；
- 不把部分地区完成的结果称为“全国最低价”。

## 用户流程与页面

工作台增加独立的“价目表批量比价”流程，使用四个连续步骤：

1. **上传图片**：拖拽或选择图片，预览文件并提示“原图不保存”；
2. **核对识别结果**：展示可编辑表格，字段为机型、容量、颜色、今日价和识别状态；
3. **全国自动比价**：展示商品进度、当前精确规格、地区进度、当前最低价、暂停、继续、停止和重试；
4. **查看结果**：默认展示“低于今日价”，另有“未发现更低价/待处理”状态列表。

一条结果必须展示：机型、容量、颜色、今日价、京东最低到手价、节省金额、完整四级代表地址、店铺、商品链接、券与国补口径、核验时间和覆盖率。

上传日期优先从图片标题识别，例如“9.3”；页面提供可编辑日期。无法可靠识别日期时默认使用本机上传日期并要求用户确认。

## 输入限制与隐私

- 只接受 MIME 与文件魔数均为 JPEG、PNG 或 WebP 的单个文件；
- 文件上限 10 MiB，解码后像素上限 20,000,000；
- 文件保存到随机命名的本机临时文件，仅供 OCR 调用；
- OCR 成功或失败后都删除临时文件；
- 数据库只保存结构化字段、OCR 原始文本片段和置信度，不保存图片二进制；
- 日志不记录图片内容、完整 OCR 文本或用户文件路径；
- FastAPI 继续只绑定 `127.0.0.1`。

## OCR 组件

使用 PaddleOCR 3.7.0 基础文字识别能力和 PaddlePaddle 3.3.0 CPU 运行时。模型首次使用时在本机下载并缓存；后续识别复用缓存。若依赖或模型不可用，接口返回 `ocr_unavailable`，页面显示安装或联网初始化提示，不退回云端 OCR。

OCR 适配器对业务层只暴露一个接口：

```python
class OcrEngine(Protocol):
    def recognize(self, image_path: Path) -> list[OcrLine]: ...
```

`OcrLine` 包含文本、0 到 1 的置信度和四边形坐标。PaddleOCR 返回结构的变化只在适配器中处理，解析器和 API 不依赖其原始对象。

## 价目表解析

首版支持“标题 + 若干规格行”的竖版手机行情表。解析器先按坐标从上到下、从左到右排序，再执行以下规则：

1. 从标题识别品牌、系列和价目日期；
2. 识别行首规格，如 `17-256G`、`17Pro256`、`17ProMAX1TB`、`17Air 256`；
3. 将同一行剩余文本解析为一个或多个“颜色 + 价格”对；
4. 把常见缩写规范化为 `iPhone 17`、`iPhone 17 Pro`、`iPhone 17 Pro Max`、`iPhone 17 Air` 和 `256GB/512GB/1TB/2TB`；
5. 将 `黑/白/紫/蓝/绿/橙/金` 规范化为对应的 `黑色/白色/紫色/蓝色/绿色/橙色/金色`；
6. 每个颜色生成一条独立记录，不合并颜色；
7. 今日价必须为人民币整数分值，手机价限定在 ¥1,000 至 ¥30,000；
8. 字段缺失、冲突或任一来源行置信度低于 0.80 时标记为 `needs_review`。

解析器不得自行丢弃低置信度行。用户确认前可以编辑、删除、新增或取消选择；确认后所选行必须满足机型、容量、颜色和价格完整且同一批次内不重复。

## 独立数据模型

OCR 价目表是临时市场基准，不属于现有标准商品目录，因此使用独立模型，不创建隐藏 `ProductVariant`，也不改变现有 `SearchSession.variant_id` 契约。

### `price_sheet_batches`

保存文件显示名、价目日期、状态、识别条数、已选条数、完成/部分/失败条数、低于今日价条数、当前规格、脱敏错误和时间。状态为：

- `reviewing`：OCR 已完成，等待用户核对；
- `queued`：已确认，等待执行；
- `running`：正在发现候选或核验地区；
- `paused`：用户暂停；
- `waiting_user`：等待登录、验证码或访问频率恢复；
- `completed`：所有所选规格均完成 31 个地区；
- `completed_partial`：队列结束但存在部分或失败规格；
- `stopped`：用户停止，保留已有结果；
- `failed`：批次级错误。

### `price_sheet_items`

保存批次、顺序、是否选择、品牌、规范化机型、容量、颜色、今日价、OCR 原始文本、置信度、状态、候选统计、31 地区统计和脱敏错误。唯一身份为 `(batch_id, model_name, storage, color)`。

候选发现完成后，将恢复所需的白名单候选保存为结构化 JSON；只保存 SKU、标题、链接、店铺、店铺类型、初始价格和匹配分数，不保存页面内容。

### `price_sheet_region_tasks`

每个已选择规格创建 31 条任务，保存省、市、区县、街道、顺序、状态、尝试次数、候选核验数、最低结果、错误和时间。唯一身份为 `(price_sheet_item_id, region_code)`。

### `price_sheet_region_results`

每个规格和地区最多保存一条可信最低报价，包含京东 SKU、标题、链接、店铺、页面价、普通券、确认国补、运费、可信到手价、价格口径标记、库存和核验时间。唯一身份为 `(price_sheet_item_id, region_code)`。

## 精确候选匹配

候选查询词为 `Apple + 规范化机型 + 容量 + 颜色`，最长 200 个字符。每个规格搜索最多 30 条原始候选，保留最多 15 条进入地区核验。

候选必须同时满足：

- 标题明确属于 Apple/iPhone；
- 型号精确匹配，`Pro`、`Pro Max`、`Air` 不能互相替代；
- 容量精确匹配；
- 颜色明确且与目标颜色一致；
- 未明确标记港版、美版、日版、韩版或海外版；
- 未明确标记二手、翻新、展示、官换或资源机；
- 不是配件、定金、分期、以旧换新或预约专享价格。

标题未明确颜色的候选不进入首版核验，避免错误颜色产生假低价。

## 地址与执行调度

31 个地址使用已批准的固定四级地址表。直辖市在数据中保留省、市字段，但插件点击时消除连续重复层级。只有页面同时确认目标区县和街道，才能读取报价。

浏览器执行器保持单工作线程，禁止并行操作京东页面。调度顺序为：

1. 按价目表条目顺序选择下一个 `queued` 规格；
2. 若无已保存候选，则搜索一次并持久化候选；
3. 按固定地区顺序核验未完成任务；
4. 每个地区完成后立即保存最低报价与进度；
5. 规格 31/31 后计算全国最低结果，再进入下一规格；
6. 所有规格结束后汇总批次状态。

生产默认每完成一个地区等待 8 秒，每 3 个地区额外冷却 60 秒；夹具测试延迟为 0。暂停发生在当前最小安全操作结束后。程序重启时把遗留的 `running` 状态恢复为 `queued`，已完成地区不重跑。

## 价格口径

可信到手价只使用以下无条件或普遍可领取项目：

```text
页面销售价
- 明确普通商家/平台优惠券
- 明确且适用于当前商品与地区的国补
+ 明确运费
```

若页面销售价明确标记为“到手价”“券后价”或“国补领后价”，适配器必须记录已包含的优惠类型，计算器不得再次扣减。优惠金额没有单独展示时可以标记“页面已含，金额未拆分”，但不能猜测金额。

会员、PLUS、指定支付、以旧换新、分期、新人和预约价格只作为排除或条件信息，不进入可信到手价。国补只有 `confirmed` 才扣减；`estimated`、`unknown` 和 `ineligible` 都不扣减。

地区无货、颜色不符、价格无法解析或依赖条件优惠的候选不参与最低价。一个地区的最低结果按 `可信到手价 → 京东 SKU` 升序选择，保证相同数据下结果稳定。

## 结果判定

- 规格只有 31 个地区全部为 `completed`，才可使用“全国 31 地区最低价”；
- 若最低到手价小于今日价，进入“低于今日价”，且只显示这一条；
- 若最低到手价等于或高于今日价，进入“未发现更低价”；
- 若任一地区失败、等待或未执行，只显示“已核验地区最低价/部分地区未核验”，不进入全国最低价列表；
- 若 31 个地区均无可信在售结果，显示“未发现可比较商品”；
- 相同最低价并列时按地区顺序、京东 SKU 选择一条。

## API

新增以下本机接口：

- `POST /api/price-sheet-batches/recognize`：请求体为原始图片字节，文件名通过 `X-File-Name` 传入；返回批次和识别条目；
- `GET /api/price-sheet-batches/{batch_id}`：读取批次、条目和汇总；
- `PUT /api/price-sheet-batches/{batch_id}/items`：一次性保存用户校对后的完整条目集合；
- `POST /api/price-sheet-batches/{batch_id}/start`：验证条目、创建地区任务并提交后台队列；
- `POST /api/price-sheet-batches/{batch_id}/pause`；
- `POST /api/price-sheet-batches/{batch_id}/resume`；
- `POST /api/price-sheet-batches/{batch_id}/stop`；
- `POST /api/price-sheet-batches/{batch_id}/retry-failed`；
- `GET /api/price-sheet-batches/{batch_id}/results`：返回低价结果、未发现更低价和部分/失败状态。

重复暂停、继续、停止和重试必须幂等。所有错误沿用结构化字段 `what_happened`、`possible_cause`、`partial_saved` 和 `next_action`。

## 失败处理

- 文件类型、大小或像素不合法：拒绝创建批次，不写入图片；
- OCR 依赖/模型不可用：返回 `ocr_unavailable`，原图仍删除；
- 无法解析任何条目：创建 `reviewing` 批次并返回空表，让用户手工新增；
- 重复或不完整条目：拒绝启动并精确标注行号和字段；
- 搜索无精确颜色候选：规格标记 `completed`，结果为“未发现可比较商品”；
- 登录、验证码或访问频率：批次和当前任务进入 `waiting_user`，用户处理后继续；
- 网络错误：最多重试两次；
- 页面变化、街道不存在或输出无效：当前地区失败，继续下一个地区；
- OpenCLI 不可用：批次级失败；
- 程序内部错误：记录脱敏摘要，保留已经落盘的进度并重新抛出供日志定位。

### 真实验收

真实京东测试由用户关闭代理后执行。先选择一个精确规格核验北京、天津和广东三个地址，确认地址、颜色和价格口径后，再启动完整批次。验证码只由用户处理。

## 完成条件

- 示例类价目表能在本机识别并生成可编辑的颜色级条目；
- 用户确认后可启动可恢复的京东批量任务；
- 每个规格确实核验 31 个四级代表地址；
- 到手价不会重复扣减已经包含的券或国补；
- 低价列表每个精确规格最多一条，且价格严格低于今日价；
- 部分地区结果不会被标成全国最低；
- 图片不进入数据库或长期文件目录；
- 后端、前端、插件和离线端到端测试及构建全部通过。
