# 京东 31 地区四级地址选择设计

## 背景

当前全国比价为 31 个省级地区各保存一个代表省、市、区，并通过 OpenCLI 在京东页面依次选择这三个层级。京东当前地址选择器要求继续选择街道或乡镇；只选择到区县时，面板仍停留在“请选择”，页面并未确认新的配送地址，后续价格和库存可能仍属于旧地址。

本次改动把每个代表地区升级为固定的四级地址，并且只有页面明确确认区县和街道后才允许读取报价。

## 目标

- 31 个省级地区分别使用一个固定且可复现的代表地址。
- 每个地址包含省级、市级、区县级和街道/乡镇级名称。
- 京东页面必须完成最后一级选择并确认新的配送地址。
- 任务、接口和页面能够展示实际使用的完整代表地址。
- 旧采集任务在数据库升级后仍具有明确的街道值。

## 非目标

- 不扩展到港澳台地区。
- 不精确到社区、村、门牌号或用户住宅地址。
- 不在本阶段增加其他电商平台。
- 不在指定街道不存在时自动换用另一个街道。
- 不改用京东联盟 API 或其他官方商品 API。

## 数据模型和兼容性

`RegionTarget` 增加必填的 `street` 字段。`CollectionRegionTask` 和对应 API 响应也增加 `street`，使每次采集运行都保存当时实际使用的地址，而不是在展示时读取可能已变化的全局配置。

数据库迁移分三步完成：先增加可空列；再按 `region_code` 为已有 31 地区任务回填本规格中的街道；最后把列约束改为非空。迁移完成后，新旧任务都满足四级地址契约。未知地区代码不会被静默填充，迁移应失败并保留原数据库状态。

前端地区任务类型增加 `street`，任务明细和错误区域使用“省 / 市 / 区县 / 街道”格式显示。全国汇总仍按省级地区统计，不改变总数 31。

## OpenCLI 接口

`price-compare-jd verify` 和 `price-compare-jd verify-region` 增加必填参数 `--street`。后端网关在 `--district` 之后传入该参数，插件命令帮助也必须公开该参数。

插件根据四个语义层级生成页面点击路径：

1. 对普通省份使用“省 → 市 → 区县 → 街道”。
2. 对北京、天津、上海、重庆，规范化名称后消除连续重复的省、市值，使用“市 → 区县 → 街道”。
3. 每一级只在当前可见的京东地址选择面板内寻找完全匹配或现有的行政后缀短名称，避免误点页面其他同名文本。
4. 选择街道后等待页面完成地址刷新，再读取报价。

## 成功判定

地址选择只有同时满足以下条件才算成功：

- 已完成最后一级街道/乡镇点击。
- 地址面板不再停留在最后一级“请选择”。
- 页面当前配送地址文本包含目标区县的可接受标签。
- 页面当前配送地址文本包含目标街道的可接受标签。

未满足任一条件时，不读取商品价格或库存。

## 失败处理

- 找不到指定街道：返回 `UNSUPPORTED_REGION`，安全信息包含完整目标地址。
- 地址列表仍在加载：返回 `NETWORK_ERROR`，保留当前地区供稍后重试。
- 点击后页面未确认区县和街道：返回 `PAGE_CHANGED`，避免把旧地址报价写入数据库。
- 登录、验证码和访问频繁继续沿用现有错误分类。
- 不自动选择列表第一项，也不自动切换备用街道。

单个地区失败不会改变其他地区的固定地址。用户可以通过现有“重试失败地区”功能再次执行。

## 测试标准

实现遵循测试驱动开发，先增加失败测试，再修改生产代码。自动化测试不得访问真实京东页面。

必须覆盖：

- 地址目录恰好包含 31 个唯一地区代码，每条记录的街道非空。
- 北京等直辖市生成三次有效层级点击，普通省份生成四次。
- 后端两个 OpenCLI 命令都传递正确的 `--street` 参数。
- 插件命令定义要求 `street`，且只有区县和街道均确认时才成功。
- 找不到街道、列表加载失败和选择未确认时返回对应安全错误。
- 数据库迁移为已有任务正确回填街道并建立非空约束。
- API 返回 `street`，前端能够展示完整四级地址。
- 现有后端、前端、插件测试和前端构建继续通过。

真实京东联调由用户关闭代理后执行。验收时至少先检查北京、天津、广东三个地址，再启动完整 31 地区任务；若某个固定街道在京东列表中不存在，则记录该地区和京东显示名称，单独修订地址表，不启用自动回退。

## 完成条件

- 31 个新建或迁移后的地区任务全部保存四级地址。
- 自动采集不会在街道仍未选择时进入报价读取阶段。
- 页面能够看到每个任务的完整代表地址和明确失败原因。
- 所有离线测试与构建通过。
- 用户在关闭代理的环境下能够开始一次四级地址全国采集测试。
