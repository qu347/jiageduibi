# 全国自动浏览器采集设计

## 状态与决策

本设计于 2026-09-02 获得用户批准，作为现有“全国多地区报价与采集会话”之后的下一阶段。第一阶段采用“本机登录浏览器批量自动采集”，不要求官方 API 密钥；以后取得平台授权密钥时，可把候选商品发现切换为官方 API 优先。通用网页爬虫只记录为备选方案，本阶段不实现，也不自动切换。

平台按京东、淘宝/天猫、拼多多的顺序接入。首个可交付版本只实现京东闭环，稳定后复用同一任务与结果模型扩展另外两个平台。全国范围固定为中国大陆 31 个省级行政区，不含香港、澳门和台湾。

## 目标

用户确认标准商品型号后，只需点击一次“开始全国查询”。软件在本机浏览器已有登录态下完成以下工作：

1. 搜索平台候选商品；
2. 排除错型号、配件、定金、二手和异常价格；
3. 依次切换 31 个代表地区，核验价格、库存、运费和明确优惠；
4. 边采集边保存并展示进度；
5. 每个平台、每个地区保留最低 10 条，默认展示前 5 条；
6. 生成带地区、平台、采集时间和来源的全国排序。

首版必须在没有官方 API 密钥的环境中可用，并能在验证码、登录失效、网络失败或程序重启后保留已经完成的结果。

## 非目标

- 不自动下单、加入购物车、提交结算或支付；
- 不绕过验证码、风控、登录限制或平台访问控制；
- 不保存平台密码、Cookie、支付信息、完整收货地址或页面 HTML；
- 不承诺覆盖平台全部商品，也不宣称结果是绝对“全国最低价”；
- 不在京东阶段同时实现淘宝和拼多多；
- 不实现通用网页爬虫、云端队列、Redis、Celery 或远程账号托管；
- 不删除现有固定夹具演示和用户点击触发的浏览器扩展采集入口。

## 已知约束与假设

- 用户当前没有京东联盟 `appKey`/`appSecret`，所以首版候选发现来自本机浏览器。
- Agent-Reach 只负责相关命令行工具的安装检查和环境诊断；业务代码不把它当作数据采集 API。
- 实际浏览器采集由 OpenCLI 的平台适配能力完成，并通过一个仓库内的窄适配器隔离命令、输出格式和退出码变化。
- 当前已确认 OpenCLI 可作为京东和淘宝能力的起点；拼多多能力尚未确认，因此不能在京东阶段声称支持拼多多。
- 地区切换只使用商品页面或平台提供的地区选择器，不修改账号默认收货地址，不填写姓名、电话、街道或门牌号。
- 若页面必须提供比区县更细的地址才能返回价格，任务以结构化原因停止或跳过，不能伪造地址。

## 总体架构

系统保持本机单进程架构：Vue 工作台调用 FastAPI；FastAPI 在同一进程中运行一个可恢复的顺序任务执行器；任务、进度和报价写入现有 SQLite；外部浏览器能力通过 OpenCLI 子进程调用。

```text
Vue 工作台
    ↓ 创建/控制采集运行
FastAPI 本机 API
    ↓
SQLite 持久任务队列 ←→ 单进程顺序执行器
                         ↓
                  OpenCLI 窄适配器
                         ↓
                  本机已登录浏览器
                         ↓
现有型号匹配 → 排除规则 → 补贴/价格计算 → 报价与快照 → 全国排序
```

只允许一个平台地区核验任务同时操作浏览器。这样会牺牲一部分速度，但能避免多个任务相互覆盖地区选择、标签页状态和登录流程。候选搜索与地区核验均由后台任务执行，HTTP 请求只负责启动或读取状态，不长时间阻塞。

## 组件边界

### 采集运行服务

一次用户查询对应一个持久化的采集运行。它保存平台、目标标准 SKU、阶段、覆盖率、候选数量、成功/失败地区数、当前地区和安全的最后错误。运行状态为：

- `queued`：等待执行；
- `running`：正在搜索或核验；
- `paused`：用户主动暂停，保留当前进度并等待继续；
- `waiting_user`：等待用户完成登录或验证码；
- `completed`：31 个地区均完成；
- `completed_partial`：执行结束但存在失败或跳过地区；
- `stopped`：用户停止；
- `failed`：候选搜索等运行级故障导致无法继续。

暂停发生在最小安全操作完成后。用户停止时不删除已保存报价。程序启动时把遗留的 `running` 运行和任务恢复为可继续状态，不能重复清除已完成地区。

### 候选发现服务

京东首版在浏览器中搜索一次目标型号，目标取得约 30 条原始候选。候选先经过现有标准 SKU 匹配和显式排除规则，再保留价格较低且可比较的 10 至 15 条进入地区核验。

以后接入官方 API 时，只替换候选发现实现：API 请求 20 至 50 条候选，仍交给相同清洗、地区核验和保存流程。来源选择顺序为“已配置且健康的官方 API → 浏览器搜索”；切换来源必须可见并记录，不能静默混用。

### 地区核验服务

地区任务按照固定顺序逐个执行。每个地区对已筛选候选核验：页面是否为同一商品、当地库存、当前销售价、已确认优惠券、明确国补、运费和安装费。每得到一条有效报价就立即写入现有报价与快照链路，不等待全部地区结束。

同一平台商品和地区重复采集更新当前报价并追加历史快照；不同地区继续使用已有 `region_key` 独立保存。地区任务不直接计算另一套排名或补贴，必须复用现有匹配、排除、补贴和价格服务。

### OpenCLI 适配器

业务层只依赖内部结构化接口，不拼接 Shell 字符串，也不解析面向人类的任意终端文本。适配器使用参数数组启动子进程，为命令设置超时，并把输出归一化为：

- `ok`：结构化候选或地区报价；
- `login_required`：需要用户登录；
- `captcha`：需要用户完成验证；
- `network_error`：可重试网络故障；
- `page_changed`：页面或输出格式不再受支持；
- `out_of_stock`：该地区无货；
- `unsupported_region`：地区选择粒度或页面不支持；
- `tool_unavailable`：OpenCLI 或浏览器桥接不可用；
- `invalid_output`：输出不满足内部契约。

具体 OpenCLI 命令、退出码和字段映射属于适配器实现细节，必须通过固定 JSON 契约测试锁定，不能扩散到调度器和 API。

## 执行流程

1. 用户确认标准 SKU，选择“全国比价”，点击“开始查询”。
2. 后端创建全国搜索会话和京东采集运行，立即返回运行 ID。
3. 预检 OpenCLI、浏览器桥接和京东登录态。未登录时进入 `waiting_user` 并提供登录操作提示。
4. 浏览器搜索约 30 条候选；匹配和排除后留下 10 至 15 条。
5. 执行器按地区表顺序核验。一个地区完成后立即更新覆盖率和结果列表。
6. 网络错误最多自动重试两次并使用短退避；解析变化和不支持地区不循环重试。
7. 遇到验证码时暂停整个浏览器执行器。用户完成验证后点击“继续”，从当前未完成任务恢复。
8. 地区级失败不阻止后续地区。结束时存在失败地区则标记 `completed_partial`，用户可只重试失败地区。
9. 全部可执行任务结束后，结果按可信价格规则生成地区榜和全国榜。

浏览器搜索没有任何有效候选属于运行级失败；候选存在但某地区全部无货属于地区完成结果，不属于系统故障。

## 恢复、暂停与错误处理

- 每个地区任务状态为 `queued`、`running`、`waiting_user`、`completed`、`failed` 或 `skipped`。
- 运行级和任务级状态都写入 SQLite；不能只保存在内存或前端。
- 崩溃恢复时，已完成任务保持完成，未落盘的 `running` 任务重新排队。
- 手动暂停与验证码等待都不占用持续重试循环。
- “继续”前重新执行轻量预检；登录仍无效时继续等待而不是报假成功。
- “重试失败地区”只重新排队 `failed` 任务，不重跑已完成地区。
- 错误记录只保存错误类别、平台、地区、适配器版本、时间和脱敏摘要；不保存页面 HTML、Cookie、账号、令牌或包含个人信息的截图。
- 用户界面始终显示真实覆盖率，例如“已核验 28/31”，不能把部分完成标成全国完成。

## 持久化模型

在不改变现有搜索会话和报价身份的前提下，新增最少的持久任务模型：

### `collection_runs`

保存 `search_session_id`、平台、状态、阶段、候选来源、候选统计、31 地区统计、当前任务、开始/更新时间和脱敏错误。一个搜索会话可以按平台建立独立运行，为后续淘宝和拼多多复用。

### `collection_region_tasks`

保存运行 ID、地区代码、显示名称、顺序、状态、尝试次数、已核验候选数、有效报价数和脱敏错误。唯一身份为 `(collection_run_id, region_code)`。

候选数据只保存完成恢复所需的白名单字段：平台 SKU、标题、商品链接、店铺标识、初始价格和匹配结果。若现有报价表能够承载最终记录，不再创建第二套最终报价表。

迁移只新增表或必要索引，不删除、重写或合并现有搜索会话、报价、快照和手动采集数据。

## 本机 API 与工作台

在现有搜索会话 API 上增加最少控制面：

- 为现有全国会话创建采集运行；
- 读取运行、地区任务和覆盖率；
- 暂停、继续、停止；
- 只重试失败地区；
- 读取自动化环境与登录预检状态。

具体 URL 在实施计划中按现有路由风格确定。所有写操作继续使用结构化错误对象；重复的暂停、继续或停止请求必须幂等。

工作台保留一个主操作“开始全国查询”，并展示：当前平台和阶段、候选数量、当前地区、完成/失败/等待数量、31 地区进度、最近安全错误，以及暂停、继续、停止和重试失败地区操作。报价一旦落盘就出现在现有结果区域，不新建第二套结果页面。

默认每个平台、每个地区显示最低 5 条，可展开至 10 条。全国榜必须同时显示地区、平台、采集时间、数据来源和核验状态。

## 价格可信度与排序

只有型号达到现有接受标准、当地有货且地区核验完成的报价进入默认排行榜。默认可比到手价继续复用现有价格计算规则：

```text
页面销售价
- 已确认商家或平台优惠券
- 已确认且适用于该地区与商品的国补
+ 明确运费
+ 明确安装费
```

会员价、指定支付方式、以旧换新、新人价和未确认优惠券作为条件价格展示，不进入默认排序。估算或资格未确认的国补不能从默认价格中扣除。未核验、解析失败、地区无货或默认可比价为空的记录不参加排名，但可以在状态统计中显示原因。

同一平台、平台 SKU 和地区按现有唯一身份去重，最新成功核验更新当前报价并追加价格历史。每个平台和地区保留最低 10 条默认可比报价；全国榜汇总所有已核验地区后按现有后端排序函数升序排列。

页面文案固定为“本次已采集范围最低价”或同等含义，不能写成未经限定的“全国绝对最低价”。

## 来源与可追溯性

每条报价保存并展示 `source_type`、平台、适配器版本、地区和采集时间。京东首版使用 `source_type=browser`；已有 `manual`、`fixture` 数据继续保持原值；未来 API 候选经浏览器核验后，需要分别记录候选来源和最终核验来源，不能只标成 API 实价。

同一结果集中可以包含历史手动数据和本次自动数据，但默认全国榜必须明确采集时间，不能让过期历史报价看起来像本次核验结果。

## 安全与隐私边界

- 后端继续只绑定 `127.0.0.1`；
- 子进程使用参数数组，不通过 `shell=True` 或拼接命令执行用户输入；
- 商品查询文本按长度和字符边界校验；
- 软件只使用用户本机已经建立的浏览器登录态，不读取或复制 Cookie；
- 日志和 API 错误不得包含账号、Cookie、令牌、完整页面或个人收货信息；
- 若以后添加 API 密钥设置，密钥不得进入普通日志和前端状态响应，也不要求用户在聊天中粘贴；
- 验证码只能暂停并请求用户处理，不提供识别、规避或自动绕过功能。

## 测试策略

实现继续遵循 TDD，每项行为先有失败测试，再添加最小实现。

### 单元测试

- 地区表恰好 31 条、代码唯一、顺序稳定且不含港澳台；
- 运行和地区任务状态转换、幂等控制与崩溃恢复；
- 网络失败最多重试两次，页面变化不自动循环；
- OpenCLI 结构化输出、超时和退出结果映射；
- 精确型号筛选、显式排除和候选 Top 15；
- 条件优惠与估算国补不进入默认可比价；
- 地区 Top 10、默认 Top 5 和全国排序；
- 日志与错误响应脱敏。

### 契约与集成测试

- 使用固定 OpenCLI JSON 和固定退出结果测试适配器，不依赖真实网站；
- 模拟 31 个地区任务，验证逐条保存、覆盖率和去重；
- 模拟验证码暂停/继续、登录失效、部分失败、只重试失败地区；
- 模拟进程在任务中断后重启，验证已完成地区不重跑；
- 验证不同地区之间不会复用错误地区状态；
- 验证手动扩展、固定夹具和既有会话 API 保持兼容。

### 离线端到端测试

无需真实平台账号即可完成：创建全国查询、候选发现、31 地区进度、验证码暂停、继续、部分完成、失败重试、全国榜展示和刷新恢复。离线测试使用仓库固定数据，不能宣称证明真实京东页面稳定。

### 真实冒烟验收

用户在本机完成京东登录后，先对一个准确型号运行北京、上海、广东 3 个试点地区。确认候选搜索、地区切换、价格口径、库存和恢复行为后，再运行 31 地区。真实冒烟测试是人工验收，不进入默认 CI，也不得在报告中记录账号或个人信息。

## 分阶段交付与成功标准

### 阶段 A：京东闭环

- 无 API 密钥时一次点击可以创建并启动运行；
- 离线环境完整模拟候选筛选和 31 地区任务；
- 真实环境能完成 3 地区冒烟，随后允许用户启动 31 地区；
- 支持进度展示、暂停、验证码等待、继续、停止、重启恢复和失败地区重试；
- 自动报价进入现有历史、地区榜和全国榜；
- 默认显示每地区 Top 5，可展开至 Top 10；
- 所有结果显示覆盖率、地区、来源、核验状态和时间；
- 不保存密码或 Cookie，不绕过验证码，不执行订单动作。

### 阶段 B：淘宝/天猫

仅在阶段 A 通过真实冒烟后开始。复用相同运行、地区、错误、价格和界面模型，只新增平台适配与真实验收证据。

### 阶段 C：拼多多

只有确认存在可维护的 OpenCLI 或官方 API 接入路径后才实施。未确认前平台状态必须保持“尚未支持/尚未验证”。

## 爬虫备选方案

本阶段只在文档中保留爬虫备选，不包含爬虫代码、开关或自动降级逻辑。只有浏览器候选搜索在多次真实验收中持续失败，或平台适配维护成本不可接受时，才重新评估爬虫。切换前必须重新确认合规边界、访问频率、数据字段、反爬失败策略和维护成本，并取得用户明确批准。

## 与现有文档的关系

本设计有意替代 `docs/data-source-policy.md` 中“真实页面必须逐页点击、禁止批量采集”的阶段性限制，但只对用户主动启动的本机批量任务生效。自动下单、凭据保护、验证码人工处理和结果不夸大等限制继续有效。

实施时必须同步更新 `docs/architecture.md`、`docs/data-source-policy.md`、`docs/platform-adapters.md` 和 `docs/testing.md`，使实际行为与文档一致。现有“全国多地区报价与采集会话”设计仍是数据模型与手动采集兼容性的基础，不被删除。
