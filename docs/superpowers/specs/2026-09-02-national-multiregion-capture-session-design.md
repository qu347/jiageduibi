# 全国多地区报价与采集会话设计

## 背景与目标

当前全国比价已经让报价携带地区，但同一会话、平台和 SKU 只能保存一条报价，扩展也没有可由工作台管理的长期采集会话。本阶段建立真实页面适配之前的稳定数据闭环：工作台创建全国采集会话，扩展验证会话后提交用户主动采集的候选报价，多地区报价独立保存，工作台预览并最终锁定结果。

本阶段继续只使用固定夹具验收。真实京东、淘宝/天猫和拼多多页面状态保持“尚未验证”，不增加真实选择器、后台爬取、自动切换地区、登录或验证码自动化。

## 核心数据模型

`SearchSession` 新增非空 `comparison_scope`，值为 `national` 或 `regional`。创建请求未提供该字段时保持向后兼容：`region_code` 为空推断为 `national`，否则推断为 `regional`。全国会话必须没有统一 `region_code`，地区会话必须提供 `region_code`；冲突输入返回结构化 422。

`Offer` 新增非空 `region_key`，由单一职责的地区身份模块生成：

- 有地区代码：`code:<region_code>`；
- 无代码且名称规范化后精确为“全国”：`national`；
- 无代码但有地区名称：`name:<规范化名称>`；
- 代码和名称都没有：`unknown`。

名称规范化只做去除首尾空白、合并连续空白和 Unicode `casefold`，不从 IP、语言、账号或 URL 推测地区。地区代码与“全国”名称同时存在属于冲突输入，必须拒绝。

报价唯一身份调整为 `(search_session_id, platform_id, platform_sku_id, region_key)`。同地区重复采集更新当前报价并追加快照；不同地区分别保存；未知地区重复采集落在同一 `unknown` 报价上，前端显示“地区未确认”。

## SQLite 迁移

新增 `0005_national_multiregion_sessions`：

1. 以可空列形式加入 `comparison_scope` 和 `region_key`；
2. 根据旧会话是否有 `region_code` 回填范围；
3. 根据旧报价的地区代码和名称回填地区身份；
4. 使用 SQLite batch alter 将列改为非空；
5. 删除旧唯一约束并创建包含 `region_key` 的新唯一约束。

升级不删除或合并报价、匹配记录和快照。降级前按旧身份分组检测跨地区重复；存在冲突时抛出明确错误并保持数据不变，没有冲突时才恢复旧约束和删除新列。迁移测试覆盖空库升级、从 0004 升级、回填、约束、可安全降级和冲突降级保护。

## 后端会话与报价流程

全国会话只使用报价自身地区；地区会话允许在报价地区缺失时回退到会话地区。地区确定后，同一组 `region_code`、`region_name` 和 `region_key` 同时用于补贴计算和报价保存，避免计算身份与持久化身份分叉。无地区的全国报价不套用任何默认城市规则，补贴状态为 `unknown`，原因改为“该报价未提供适用地区，无法匹配地区补贴规则”。

新增只读预览接口 `GET /api/search-sessions/{id}/result`。共享的 `build_search_result` 负责查询可见报价、排除数量和排序；预览不改变状态、不写快照，完成接口只负责把 `collecting` 转为 `completed` 后调用同一构建逻辑。完成会话后所有报价写入入口继续拒绝写入。

默认排序统一调用 `backend/app/pricing/sorting.py` 的 `sort_offers`，只使用 `comparable_price_cents`、店铺优先级、采集时间和 ID。估算补贴和所有条件价都不进入默认排序。

为页面刷新恢复标准 SKU，增加只读 `GET /api/catalog/variants/{id}`；它只返回现有目录中的标准变体，不创建或修改目录数据。

## 工作台状态机

比价 store 拆分为明确动作：

- `createCollectionSession`：为已确认 SKU 创建 `national`、`collecting` 会话；
- `refreshCollectionSession`：调用预览接口读取扩展已提交报价；
- `finalizeCollectionSession`：完成会话并读取最终结果；
- `restoreCollectionSession`：从本地 ID 恢复标准 SKU、会话和预览；
- `runFixtureComparison`：独立的固定夹具演示，自动创建、导入并完成。

工作台在确认 SKU 后显示两个清晰入口：浏览器采集会话和固定夹具离线演示。采集卡显示会话 ID、状态、全国范围和目标 SKU，并提供复制、刷新、完成和重新创建操作。重新创建只创建新会话，不删除旧会话或历史。

本地存储只保存 `lastSessionId` 和 `lastVariantId`。页面加载时恢复 ID，读取会话和标准 SKU，校验二者一致后再读取预览。会话不存在时清除失效记录；SKU 不一致时不挂载并提示；后端不可达时保留 ID；已完成会话可查看但不能继续采集。不自动新建、不自动轮询。

## 报价与最低价展示

条件价开关只控制条件价文字是否可见，`selectVisibleOffers` 始终保留后端顺序。每条报价直接显示 `适用地区：<region_name | region_code | 地区未确认>`。

最低标记只基于非空 `comparable_price_cents`。并列最低时汇总去重后的地区名称；少量地区完整列出，超过三个地区显示“首个地区等 N 个地区”，完整地区仍可在各报价行看到。全部报价都没有可靠价格时不显示排名和最低价地区，显示“暂无可靠可比价”。明确的 `national` 报价才显示全国；多个地区同价不推断为全国。

## 扩展会话流程

弹窗把 `searchSessionId` 保存到 `chrome.storage.local`，打开时恢复。采集按钮按顺序验证：本地服务、配对令牌、会话 ID、会话存在、状态为 `collecting`、范围为 `national`、当前页面解析结果。只有全部通过才向扩展报价接口提交。

扩展读取后端 `accepted_count`、`excluded_count` 和 `exclusions`，区分接受、全部排除、会话无效、认证失败、服务不可达、登录、验证码、站点不支持和缺少一次性总价。令牌不进入日志或页面。

内容脚本通过可测试的 `installCaptureListener` 和文档级唯一标记实现幂等安装。同一文档重复注入只注册一次；页面导航产生的新文档可以重新注册。不增加持久平台 host 权限、`<all_urls>` 或其他 manifest 权限。

## 错误与兼容性

搜索会话 API 的业务和校验错误继续使用 `what_happened`、`possible_cause`、`partial_saved`、`next_action`。预览不存在的会话返回结构化 404；写入已完成会话返回结构化 422。扩展把安全的后端原因映射为用户可执行的中文提示，不回显令牌或内部堆栈。

旧客户端省略 `comparison_scope` 仍可工作。现有地区会话、报价、快照和历史全部通过迁移保留。后端仍绑定 `127.0.0.1`，数据库仍为本地 SQLite。

## 测试与验收

实现遵循 TDD：每项行为先写能够因缺少实现而失败的测试，再写最小实现。

后端覆盖范围推断与冲突、地区身份、同 SKU 同/不同地区、独立地区补贴、预览与完成一致、条件价排序不变量、完成后写入保护和迁移升降级。前端覆盖会话创建/复制/刷新/完成/恢复、失效恢复、每条地区、并列最低、无可靠价格和条件价顺序不变。扩展覆盖会话 ID 持久化与校验、提交反馈、认证与服务错误、监听器幂等和权限边界。

离线 E2E 使用四条有效地区报价：京东上海、京东北京、淘宝深圳、拼多多北京。它验证同一京东 SKU 的两个地区同时存在，默认顺序为 4999、5049、5099、5199，条件价开关不改变 ID 顺序，刷新恢复会话，完成后拒绝写入，同时保留独立离线演示入口。

最终运行构建、完整测试、演示脚本和各子项目单独命令，记录退出码、测试数量和耗时。随后在 Microsoft Edge 检查生产演示、窄屏和扩展弹窗。真实网站状态始终保持 `not_validated`。
