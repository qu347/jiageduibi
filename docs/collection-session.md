# 全国采集会话

## 范围

`comparison_scope=national` 表示一个会话可接收多个适用地区的报价。它只覆盖用户实际采集或固定夹具提供的地区，不会后台遍历平台，也不能证明未采集地区没有更低价格。

## 生命周期

1. 工作台在用户确认标准 SKU 后创建会话，初始状态为 `collecting`。
2. 扩展保存 `searchSessionId`，每次采集前读取后端会话，要求范围为 `national` 且状态为 `collecting`。
3. `GET /api/search-sessions/{id}/result` 只预览当前结果，不改变状态。
4. `POST /api/search-sessions/{id}/finalize` 把会话变为 `completed`，并按与预览相同的规则返回结果。
5. 已完成会话拒绝新报价；需要继续采集时必须在工作台新建会话。

工作台把最后一次会话 ID 与 SKU ID 保存在浏览器本地存储。刷新页面时按“会话、SKU、结果”恢复；仅后端明确返回 404 时清除记录，网络故障不会丢弃 ID。

## 多地区报价身份

报价唯一身份是 `search_session_id + platform_id + platform_sku_id + region_key`。地区编码优先生成 `code:<编码>`；只有地区名时使用规范化名称；全国适用、未知地区分别使用独立键。同一 SKU 的上海与北京报价可并存，同一地区再次采集会更新当前报价并追加价格快照。

## 默认排序与补贴

预览和完成共享默认排序。排名只看可靠的 `comparable_price_cents`，不会用会员、支付、以旧换新条件价，也不会用预计补贴价重新排名。每条报价独立匹配地区补贴；缺少地区时显示未知原因。平台对同一 SKU 明确确认的补贴仍可进入默认可比价。

## 当前限制与阶段 2 前置条件

当前验收使用上海、深圳、北京等固定地区报价和保留域名数据。真实购物网站的选择器、地区切换、登录/验证码状态、库存和结算价均未验证。阶段 2 前应逐平台收集用户授权的人工样本，记录地区、页面结构、适配器版本和结算差异，再决定是否扩大真实采集范围。
