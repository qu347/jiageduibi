# Architecture

## Components

- FastAPI：本机 API、SQLite 访问、目录匹配、价格与补贴计算、静态前端服务。
- Vue：单页比价工作台、历史价格、平台状态。
- 自动采集协调器：单工作线程执行候选搜索与 31 地区顺序核验，支持暂停、恢复和停止。
- Agent-Reach / OpenCLI：Agent-Reach负责安装诊断；运行时由后端直接调用 OpenCLI 和项目只读京东插件。
- MV3 扩展：一次性配对和用户点击触发的当前页采集。
- SQLite：唯一业务数据库，包含目录、搜索、自动任务、候选白名单、地区进度、报价、快照、规则和设置。

## Loopback Trust Boundary

服务绑定 `127.0.0.1:8765`。扩展只拥有回环地址的持久访问权限；平台页面访问依赖用户点击后临时授予的 `activeTab`。配对令牌通过 `Authorization: Bearer` 提交，数据库仅保存哈希。

## Data Flow

1. 用户输入常用名称，后端返回标准型号。
2. 用户明确选择容量、版本和成色，创建 `comparison_scope=national` 的采集会话。
3. 自动模式搜索候选并过滤错型号、配件、定金和重复 SKU，再按固定 31 地区逐个核验；手动扩展仍作为备用。
4. 每次浏览器核验完成后立即提交报价；网络错误最多重试两次，登录或验证码进入等待用户状态。
5. 后端执行显式排除，再计算默认可比价与补贴状态。
6. 每个平台地区保留当前前 10 条，价格快照继续保存；前端按全国顺序默认显示每组 5 条，可展开至 10 条。

## Database

Alembic 迁移依次创建产品目录、报价/快照、补贴规则与本地设置。会话用 `comparison_scope` 区分全国与地区模式；报价用 `region_key` 把同一会话、平台和 SKU 的不同地区记录分开，同地区重复采集只更新当前报价并追加快照。平台 SKU 缺失时，用商品 URL、店铺标识和标题的规范化 SHA-256 作为降级去重键。

预览与完成结果调用同一个排序函数：可靠默认可比价升序、店铺类型、采集时间倒序、报价 ID。条件价和估算补贴不参与默认排序。

自动采集运行和 31 个地区任务均持久化。应用重启时只把中断的 `running` 工作恢复为 `queued`，已完成地区不重跑；协调器始终只有一个工作线程，避免多个任务同时操纵同一登录浏览器。

## Extension Communication

本地设置端点生成一次性 6 位码。扩展兑换令牌后，只在用户点击“采集当前商品页”时校验全国采集会话并注入 `capture.js`；同一文档重复注入只安装一次消息监听器。扩展不会定时运行、枚举其他标签页或访问登录凭据。
